# UE5級VSM 実装計画 — フットプリント(導関数)LODへの移行

> 独立3案 → 敵対的レビュー → 統合 のワークフロー(2026-07-13)で確定。
> 敵対レビューが提案1の「非対称帯」バグを検出し、提案2のHZB/LRU肥大化を除外、
> 提案3の固定per-level予算を不要と判定した結果の**ブレンド案**。

## 1. 根本原因

視点高さ(カメラY=1.84m, 俯角約-13°)の「ページ数爆発→ブロック破綻」は、
`Shaders/Vsm/Vsm.hlsli:20-25` の `Vsm_SelectLevel()` がクリップマップレベルを
**カメラからの光空間チェビシェフ距離のみ**で決めることに起因する
(`d = max(|lx-camx|,|ly-camy|)*2; lvl = ceil(log2(d/baseExtent))`)。

画面が実際にその解像度を要するか無関係に、カメラ近傍半径内の全ライト空間テクセルに
細レベルを刻印する。視点高さでは擦過した地面が画面の大半を占め、近傍部が細レベル(L4/L5)を
64×64=4096ページの窓ほぼ全域に要求 → 複数の細レベルが同時飽和(実測 L5≈4316 + L4≈4146) →
9216プールを溢れさせる。

**修正の本質**: レベル選択を「距離」→「スクリーン導関数(フットプリント)」へ。
1スクリーンピクセルがライト空間XYに投影される幅
`f = max(|d(lightXY)/dScreenX|, |d(lightXY)/dScreenY|)` を求め、
`texelWorld(L) >= f` の最小レベル `L = ceil(log2(f/texelWorld0))` を選ぶ。
擦過/遠方の地面は自動的に**粗レベル**を選び、要求ページ総数は「見えている地面の広さ」でなく
「スクリーンピクセル数(固定)」で上限化される。1080pでの現実的ワーキングセット ≈ 800〜1500ページ
(9216に対し >6倍余裕)。**過去に失敗した距離LODとは構造的に別物の修正。**

## 2. 採用アーキテクチャ(ブレンド)

- **フットプリントLOD** を `Vsm.hlsli` に純関数追加。丸めは `ceil`(粗い方向=1画素あたりテクセル≤1)。
- **`max(distanceLevel, footprintLevel)` 合成**。俯瞰では `footprint<=distance` → `max=distance` →
  **現行の動作ビューがビット単位不変=構造的な非回帰保証**。フットプリントは現行が溢れる箇所でのみ発火。
- **マーカー(CS)とサンプラ(PS)一致は対称±1帯 `[L-1, L+1]`**(提案1の粗方向のみ帯は誤り, §4)。
- **既存機構は全流用・不変**: トロイダル永続キャッシュ / FIFOリング退去 / 同フレーム退去防止 /
  近似LRUタッチ / ビニングcaster cull / VSM+CSMハイブリッド。LOD選択のみ差し替え。

**本バグのスコープ外**(敵対レビューが除外):
- LRUアロケータ置換(FIFOはページ数上限化後は問題なく動く)
- static/dynamic ページ分離(町は100%静的で近期の見返り無し)
- shadow-space HZB(疎アトラス上のper-level HZBはXL・高リスク, caster cull時間を改善するだけでバグを解かない)
- per-level固定予算(数が~1-2k<<9216に収まれば既存グローバル degrade=`0xFFFF`→CSM が稀な溢れをカバー)

## 3. フェーズ

### Phase 0 — 計測ハーネス(挙動変更なし) 〈S: 2-3日〉
per-levelの要求/常駐ページカウンタ + readback、env フラグ `DX12_VSM_FPLOD`(既定OFF)配線。
- `Source/Graphics/VsmSystem.cpp` — readback経路にper-level集計。`LastRequestedPages/LastResidentPages`(`VsmSystem.h:61,66`)をper-level拡張。
- `Source/Graphics/VsmSystem.h` — per-levelメンバ + 新規カウンタバッファ。
- **ゲート**: フラグOFFで両ビュー現行とピクセル一致(diff==0)・FPS不変・新規デバッグレイヤエラー無し。
  ログが視点高さの溢れ(L5≈4316,L4≈4146,総数>プール)と俯瞰の低カウントを**per-levelで**再現。

### Phase 1 — フットプリントLOD(根本修正・ロックステップ・帯なし) 〈M: 1-1.5週〉
距離LODを `max(距離,フットプリント)` に差替え。マーカー/サンプラ/デバッグを `DX12_VSM_FPLOD` で同時切替。
- `Vsm.hlsli` — `Vsm_SelectLevelFootprint(dLdx,dLdy,texelWorld0,levelCount)` +
  `Vsm_SelectLevelCombined(...)=max(...)`。`texelWorld0=Vsm_LevelCenterExtent[0].w`。旧関数は温存。
- `VsmPageMark_CS.hlsl main()` — 隣接画素`(id+1)`の深度を追加Loadし有限差分で `dLdx/dLdy` を構築。
  深度不連続ガード(閾値超/`d>=1`は片側差分を捨て反対軸)。line38 を `Combined` に置換。`MarkCb`に`gUseFootprintLod`。
- `TownPS.hlsl VsmShadowTap:54-67 / SampleSunShadowVSM:69-85` — 関数入口で `dLdx=ddx(ls.xy),dLdy=ddy(ls.xy)`
  を**[unroll]タップループ外・非一様分岐前(一様スコープ)**で計算。`L` を `VsmShadowTap` に引数で渡す
  (タップ毎の `Vsm_SelectLevel` 再計算を廃止)。PCF半径 `LevelCenterExtent[L].w*1.5` 維持。
- `VsmShadowDebug_*.hlsl` — 同置換でデバッグ表示を本番と一致。
- `VsmSystem.cpp` — `DX12_VSM_FPLOD` を全経路ロックステップ配線(片方だけだとサンプラが未マークページを読む)。
- **ゲート**: 標準視点高さ擦過ビューで `要求+常駐` が溢れ(>9216)→**3000未満**(per-level HUDで確認)。
  フラグOFFで俯瞰がPhase 0とビット一致。残存の穴/フリッカはミスマッチ画素として記録しPhase 2へ。

### Phase 2 — 対称帯マーク + シルエットガード 〈M: 約1週〉
マーク集合をサンプラの選ぶ任意レベルの厳密上位集合に。**対称帯 `[L-1,L+1]`**(§4)。
- `VsmPageMark_CS.hlsl main():38-53` — 単一レベルマークを `L in [max(L-1,0), min(L+1,gMaxMarkLevel)]`
  ループに。各Lでper-levelの`pw`を再計算しpacked絶対ページを再構築。深度不連続ガード本格実装。
- **ゲート**: 視点高さ静止+パン10秒でCSM帯以外のVSM被覆穴ゼロ。ページ数<3500。俯瞰はPhase 1と同一。
  10秒オービットでフリッカ無し(`LastResidentPages`分散<15%)。シルエットのCSM画素率がPhase 1閾値未満。

### Phase 3 — 既定ON + プール/被覆チューニング + 移動安定性 〈M: 約1週〉
`DX12_VSM_FPLOD` を既定ON。上限化の恩恵でVRAM/被覆最適化。長時間移動でキャッシュ/退去が破綻しない確認。
- `VsmSystem.h:29 kAtlasPagesPerRow` 96→~64(576MB→256MB)を**検討**(実測WS<<4096の場合のみ)。
- `gMaxMarkLevel`(`VsmPageMark_CS.hlsl:20,39`)引き上げ → 遠景の粗地面をCSMでなくVSMで賄い被覆を町全域へ拡張。
- FIFOリング/同フレーム退去防止/近似LRUタッチは不変(容量余裕下で動作)。
- **ゲート**: 町全域トラバース(歩+飛,数分)でプール無溢れ(`LastResidentPages<kPhysicalPages`常時)。
  VRAM削減。VSM影が地平線まで延び退去チャーン/明滅無し。視点高さフレーム時間 ≤ 現行俯瞰VSMコスト。俯瞰非回帰。

## 4. マーキングmip vs サンプリングmip 自己整合性(最重要リスク)

マーカーは**CS内隣接画素有限差分**、サンプラは**PSハードウェア`ddx/ddy`**で導関数を得る。
両者は深度不連続・クアッド端・シルエットで異なるレベルに量子化し得る。ミスマッチ画素は
サンプラが未割当ページ(`0xFFFF`)を読み→CSM→スペックル/穴。対策3重:
1. **対称±1帯マーク(Phase 2)** — マーク集合をサンプラの選ぶ任意レベル(L-1含む)の上位集合に。
   提案1の粗方向のみ帯`[L,L+1]`は**誤り**(サンプラの細方向L-1を取りこぼす)。
   シルエットガードは差分の破棄(反対軸採用)にとどめ、**レベルを上げる方向には使わない**。
2. **同一のclamp済みフットプリント式**をマーカー/サンプラ/デバッグで共有し丸め(`ceil`)一致。
3. **VSM+CSMハイブリッドフォールバック保持** — 残存ミスマッチと遠方edge-on面のクリップマップ窓超えを
   黒穴でなく緩やかなCSMに。**非交渉。**

予備手段(対称帯でも残る場合): page-markingを前方TownPSに移し(1フレーム遅延許容)マーカー/サンプラが
同一導関数を共有(提案3 Phase3)。改修面が広がるため対称帯で足りるなら不採用。

## 5. スコープの正直な明示

- 実効期間 **約3〜4週**。Phase 0=2-3日, 1=1-1.5週, 2=約1週, 3=約1週。全変更がLOD選択ローカルで
  トロイダルキャッシュ/FIFO/ビニング/ハイブリッドは無改修 → リスク・改修面最小。
- **Phase 1単独で対象バグ(視点高さ崩壊)は完全に治る**。Phase 0は証明のため、2は綺麗さ、3は常用化。
- フットプリント式の正当性は実定数で再検証済(`texelWorld(L)=2^L/2048 m`, `ceil`丸めで distinctマークページ
  はクリップマップ窓面積でなく**スクリーンピクセル数で上限化**)。「few hundred」は楽観寄り、「~2000」上限が堅実。
- **本計画が扱わない既知の別問題(要周知)**: 約24msのビニング床(全~30kキャスタ×8レベルを毎フレーム走査,
  `VsmCasterCount_CS`)。**どのLOD案もこれを改善しない** — ページ数を治しても移動の滑らかさはビニング律速のまま。
  真の滑らかさにはReleaseビルド+ページ/クラスタ単位caster cull(別途作業)が必要。

## 6. ユーザに委ねる最重要の未決事項(Phase 3で確定)

**プール縮小(`kAtlasPagesPerRow` 96→64, 576MB→256MB)でVRAM回収を優先するか、
9216のままVSM被覆を町全域へ拡張(`gMaxMarkLevel`引き上げ)する方に全プールを充てるか。**
両者は同じプール予算を奪い合う。実測(Phase 0/1のper-levelカウンタ)が出るまで確定不可だが、
方針(VRAM予算 vs 影被覆範囲)を先に決めるとPhase 3の目標が一意化。
プロジェクトゴール「UE5級ビジュアル」からは被覆拡張優先が整合的だが、将来のDXR GI/反射のVRAM需要と競合する。
